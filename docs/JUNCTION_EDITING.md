# Explicit source-line junction editing

This is a bounded HLS-107 increment, not complete architectural editing or physical proof.

## Deliberate membership

Choose two to sixteen endpoints from distinct native wall/window SVG lines that already
share one exact coordinate. Choose each line and its A/B endpoint deliberately, then
enter one target in drawing units. Preview must display every selected line's complete
before/after coordinates and linked-source impact before Apply. Truncated source-impact evidence rejects rather than allowing partial
review. No records are deleted to fit that review bound. Unselected endpoints at
the same coordinate remain stationary and are identified as such.

No proximity-based membership, snapping, automatic join repair, inferred adjacency,
opening/door hosting, path/polyline/polygon vertices or calibrated physical dimensions
are included. A moved straight segment may become oblique; shared coordinates alone do
not establish construction correctness. No-op and line-collapse targets are rejected.

## Trusted source and policy

Request syntax alone provides no authority. The adapter resolves actual current source,
unique native line ownership and supported root coordinates itself. All four native
`x1`, `y1`, `x2`, `y2` attributes must be explicitly numeric; implicit SVG defaults and
unit-bearing coordinate attributes are unsupported. Request-provided
geometry or lock flags are never trusted. Ambiguous/missing IDs, derived segment ownership,
unsupported coordinate contexts, protected dimensions, definitions/markers, hidden or
locked members/ancestors must reject. The first profile rejects any source containing a stylesheet and any selected line
with inline styles on the line or any ancestor; it does not attempt to evaluate CSS or
strip styling. Presentation visibility values must be recognized explicitly; unresolved
CSS values are unsupported rather than assumed visible. Visibility
that cannot be safely established stays unsupported. The default demo uses paths, so
it has no eligible native-line members; no conversion or guessed ownership occurs.

Preview binds exact source, project/state/revision identity and full current visibility/
lock policy. Some visibility settings save without a new state token, so token equality
alone is insufficient. Apply regenerates the composition against current trusted data and
compares it with the reviewed proposal. It never accepts arbitrary source-textarea edits
or calls separate single-line edits in a loop.

All selected coordinates change together in one guarded mutation and one reversible
history step. Opposite endpoints, unselected elements, IDs, attributes, source order,
dimensions/labels and non-source project data stay intact. Failed persistence or validation
must roll back the whole transaction and expose the failure. Cancel discards the proposal.
Existing anchors, chains, openings, boundaries and saved reports retain their recorded
source hashes; changed source makes that evidence stale instead of rewriting it to pass.

## Compatibility and acceptance

The source-operation namespace remains separate from overlay operation v1 and full-source
replacement. The site and a future deliberate import route must share validation, but no
imported-operation route or live provider capability is claimed by this increment.
Project, declaration and historical consistency-checker schemas remain unchanged.

Fabricated production-function verification must cover explicit A/B membership, complete
preservation, stale source and direct policy changes, protected dimensions, source locks,
quota/history failure, cancel and exact Undo/Redo. Program-level verification is separate
from native XML/input/readability acceptance and actual private-project acceptance.
Before any household reload or edit, preserve a fresh complete current private UI export.
